## 原因

原预注册 Fault 网格包含 24 candidates × 5 feature families × 5 fixed folds，即 600 次全量拟合；RandomForest 每次使用 300 trees 和约 129,280 Development windows。实测 F0 仅完成 7/24 candidates 已耗时显著，完整 F0–F4 预计需要数小时，不符合 bounded-resource 目标。

停止时已有 7 个 F0 run JSON：3 LogisticRegression 和 4 RandomForest。没有打开或查看这些文件中的 recall、PR-AUC、confusion matrix、fold variance 或任何其他数值指标。没有 HGB、F1–F4 或 summary/report 结果。

## 修改

五个 feature families 均固定使用以下 10 个代表组合：

1. LogisticRegression: `C=0.1, class_weight=balanced, max_iter=2000`
2. LogisticRegression: `C=1.0, class_weight=balanced, max_iter=2000`
3. LogisticRegression: `C=10.0, class_weight=balanced, max_iter=2000`
4. RandomForestClassifier: `n_estimators=300, max_depth=8, min_samples_leaf=5, max_features=sqrt, class_weight=balanced_subsample`
5. RandomForestClassifier: `n_estimators=300, max_depth=12, min_samples_leaf=2, max_features=sqrt, class_weight=balanced_subsample`
6. RandomForestClassifier: `n_estimators=300, max_depth=null, min_samples_leaf=1, max_features=sqrt, class_weight=balanced_subsample`
7. HistGradientBoostingClassifier: `max_iter=150, learning_rate=0.03, max_leaf_nodes=15, l2_regularization=1`
8. HistGradientBoostingClassifier: `max_iter=150, learning_rate=0.05, max_leaf_nodes=31, l2_regularization=1`
9. HistGradientBoostingClassifier: `max_iter=150, learning_rate=0.10, max_leaf_nodes=15, l2_regularization=0`
10. HistGradientBoostingClassifier: `max_iter=150, learning_rate=0.10, max_leaf_nodes=31, l2_regularization=0`

该选择在查看任何 Fault 数值结果前完成，原则是覆盖全部算法族、三个线性正则强度、浅/中/不限制 RF capacity，以及低/中/高 HGB learning rate 与两种 leaf capacity。已有 JSON 只有在 algorithm 和 hyperparameters 与新网格完全一致且 Dataset/Feature/Fold/Git lineage 验证通过时才复用；其他文件不参与 selection，并在最终结果清单中标记为 excluded pre-amendment run。

以下内容不变：

- F0–F4 和同一个固定五折 manifest；
- train-fold-only scaler/condition baseline；
- threshold `0.50`；
- macro recall `>= 0.70` 和 healthy recall `>= 0.60`；
- stability score、PR-AUC 和 tie-break 顺序；
- Paderborn Frozen Test 保持关闭，直到 Development candidate 完全冻结并提交 final config。
