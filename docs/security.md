# 安全说明

## 设备操作

- AI、规则服务和前端都不能直接调用设备命令。
- 高风险操作先写入待审批记录；主管/管理员填写意见后，批准接口才调用 Gateway。
- 重复批准返回原执行结果，不重复执行命令。
- 驳回、失败、执行结果、审批人和时间均持久化。
- 高风险维修工单开始或暂停后继续执行前，API 强制校验全部必做安全检查项，并要求工程师在同一请求中提交现场确认说明；确认人、时间和说明写入工单状态历史。
- Mock 结果不能解释为真实 PLC 或现场设备状态。

设备命令使用审批记录中持久化的 `execution_key` 作为幂等键。批准时先通过数据库条件更新将状态从 `pending` 原子认领为 `executing`，只有认领成功的请求可以调用 Gateway；其他请求遇到 `executing` 状态时必须停止自动重发并提示人工核验。执行结果已经落库时，重复批准直接返回首次结果。所有真实 Equipment Gateway 适配器仍必须持久化该键，并为重复键返回首次执行结果，不能再次下发物理命令。

`executing` 超过 `EQUIPMENT_COMMAND_TIMEOUT_SECONDS` 后转为 `execution_unknown`。主管或管理员必须记录现场设备状态、核验结论和说明：确认已执行则关闭为已批准，确认失败则关闭为执行失败，确认未执行则生成新 `execution_key` 并回到待审批。核验接口本身永远不下发命令；每次认领、完成、超时和核验都写入独立审计事件。

## 权限

- 管理员和主管：仿真控制、审批、验收、Agent 审计与调度。
- 维修工程师：查看资产/诊断，执行被分派工单；不能审批高风险操作。
- 服务端校验角色、被分派人和状态机，隐藏按钮不是唯一安全措施。

## 密钥与日志

- `.env`、数据库 URL、Redis URL、JWT Secret、LLM Key 和平台 Token 不进入 Git。
- 浏览器只使用相对 `/api`；服务端密钥不得使用 `NEXT_PUBLIC_*`。
- 日志只记录 Provider 名称、状态、耗时和脱敏错误，不打印请求头或连接串。
- CI 固定 `AI_ENABLED=false`，不访问付费模型或生产服务。

## 生产要求

生产发布前必须更换本地占位 Secret，使用 TLS 数据库/Redis，精确设置 CORS Origin，禁用自动 Seed，并配置真实 AI Provider 或明确关闭解释型 LLM 功能。生产不应把 Mock AI 输出标记为真实诊断。
